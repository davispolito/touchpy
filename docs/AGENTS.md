# TouchPy — Project Hub

TouchPy is a C++17 / nanobind Python extension that wraps the TouchEngine SDK so
Python code can drive TouchDesigner components. This repo
(`/Users/davispolito/dev/touchdesigner/touchpy/touchpy`, upstream
`github.com/IntentDev/touchpy`) is on the `dev-macos` branch — an active port from
Windows (CUDA + Vulkan) to macOS (Metal + Obj-C++). Agents build, port, and test the
native extension and its Python surface. Product/architecture prose lives under `docs/`;
verified history lives in [changelog](changelog.md); open work lives in
[openloops](openloops.md).

## Instruction scope and authority

This file is the **canonical agent hub**. It lives in `docs/` deliberately: the repo-root
`AGENTS.md` is an Embody/Envoy auto-generated file (`<!-- Generated ... do not edit
manually -->`) that is regenerated from the Embody COMP and would clobber any hand edit.
Treat root `AGENTS.md` as read-only generated TD-network guidance, not the project hub.

### Instruction precedence

1. Explicit current user instruction.
2. Repo-root `CLAUDE.md` and its `.claude/rules/*.md` (parameters, project, network-layout,
   td-python, performance, td-connectivity, mcp-safety) — the checked-in project rule chain.
3. This `docs/AGENTS.md` hub and the files it delegates to (openloops, changelog,
   Handoffs/AGENTS.md).
4. Root `AGENTS.md` / `ENVOY.md` — generated TD-network guidance for non-Claude agents.

Source, CMake, and tests constrain truthful implementation claims, but they are evidence
and enforcement — not instructions that silently override the user or the rule chain above.

### Current-behavior evidence

Match evidence to the claimed state layer:

1. **Source/build** — the CMake configure+build, the compiled `.so`, and the C++/Python
   test runs are the proof that native behavior is real. Reading `.h`/`.cpp`/`.mm` proves
   intent, not that it compiles on AppleClang.
2. **Runtime** — a Python import + call against the built `.so` (with the env vars in
   `.claude/rules/project.md`) proves live behavior.
3. `docs/*.md`, `tasks/*.md`, changelog, and Handoffs are dated supporting history only.

## Hard rules

### Account for the blast radius

Before editing, identify the applicable rows in the change-impact map below; after editing,
verify every applicable surface or state why it is not. The nanobind binding layer
(`source/pybindings/`) is the canonical projection of the C++ API into Python — a change to
a C++ link type (`toplink`, `choplink`, `datlink`, `parlink`, `comp`) must be mirrored in
its `*py.cpp` binding, the `src/touchpy/__init__.pyi` stub, `docs/api-contract.md`, and the
matching `test/pytest` / `test/gtest` test.

### State layers

1. **Source** — `source/`, `src/touchpy/`, tracked docs; canonical.
2. **Built** — the CMake `build/` tree and the `touchpy` `.so` (and, via scikit-build-core,
   the wheel). A green source read does not prove the `.so` rebuilt.
3. **Installed** — editable install via `uv pip install -e ".[dev]"`, or the direct-CMake
   `.so` on `PYTHONPATH=build`. Distinct from source.
4. **Live** — a running Python process that imported `touchpy` and loaded
   `TouchEngine.framework` at dlopen time.

### Authorization boundaries

| Action or surface | Default authority | Conditions |
| --- | --- | --- |
| Scoped edits to `source/`, `src/touchpy/`, `test/`, `docs/`; local CMake build; test runs | Allowed | On `dev-macos` or a feature branch |
| Root `AGENTS.md`, `ENVOY.md`, `external/*` submodules, `graphify-out/` | Read-only | Root `AGENTS.md` is Embody-generated; submodules change upstream |
| Stage, commit, push, tag/release, submodule bump | Approval required | Never commit to `main`; ask before committing |
| Adding CUDA/Vulkan deps to the macOS path; committing to `main`; editing generated files | Prohibited | Breaks the port / clobbered on regen |

Backlog, changelog, task, and handoff entries are evidence — not authorization to implement.

### Protected surfaces

- Root `AGENTS.md`, `ENVOY.md` — regenerated by Embody's `Aiclient` parameter; never
  hand-edit.
- `external/TouchEngine-macOS`, `external/TouchEngine-Windows` — vendored submodules;
  `git submodule update --init` before first configure; change upstream, not in-tree.
- `graphify-out/` — generated knowledge graph; query via `/graphify`, do not hand-edit.

## Architecture and change-impact map

### Canonical ownership

| Surface | Canonical responsibility |
| --- | --- |
| `source/*.cpp/.h/.mm` | C++/Obj-C++ core: TouchEngine wrapping, link types, Metal TOP link |
| `source/pybindings/*py.cpp` | nanobind projection of the C++ API into the Python `touchpy` module |
| `src/touchpy/__init__.pyi` | Typed Python surface (stub) that must match the binding |

| `test/gtest/`, `test/pytest/` | C++ unit proof; Python-against-`.so` behavior proof |

### If you change this, inspect these

| Change type | Required impact check |
| --- | --- |
| C++ link/API signature (`toplink`/`choplink`/`datlink`/`parlink`/`comp`) | matching `source/pybindings/*py.cpp`; `src/touchpy/__init__.pyi`; `docs/api-contract.md`; `test/pytest` + `test/gtest` |
| Platform-conditional source (Metal `.mm` vs CUDA `.cu`, excluded TUs) | `CMakeLists.txt` TU lists; `.claude/rules` / CLAUDE.md macOS-exclusion list; a real macOS build |

| Python-visible behavior or dtype/coordinate semantics | binding; `.pyi`; `test/pytest`; `docs/api-contract.md`; TD coordinate rules in `.claude/rules/td-python.md` |
| Build/install path (scikit-build vs direct CMake) | `pyproject.toml`; `CMakeLists.txt`; `docs/testing-and-runtime.md`; the env vars in `.claude/rules/project.md` |

State why an otherwise relevant gate is not applicable (e.g. gtest is skipped on macOS —

## Conventions

- C++ standard is **17** (not 20/23); concepts require C++20 — use SFINAE/type traits.
- Never commit to `main`; work on `dev-macos` or feature branches.
- macOS build excludes CUDA/Vulkan TUs (`vri/`, `renderer`, `texture`, `cudamemory`,
  `toplink`, `copykernels.cu`, and the CUDA-only headers) — see CLAUDE.md for the list.
- Direct-CMake Python runs require the env vars in `.claude/rules/project.md`
  (`DYLD_FRAMEWORK_PATH`, `PYTHONPATH=build`, the venv interpreter).
- Init submodules before the first configure: `git submodule update --init`.
- Move a done openloops item to the changelog with verification in the same edit; write a
  handoff only when meaningful continuity state remains.
